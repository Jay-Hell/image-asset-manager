# Image Asset Manager 1.1.0 — App Store text

macOS only. Version 1.1.0, build 4 (the released copy is 1.0.1, build 3).

## What's New in 1.1.0

Image Asset Manager now works with two providers, and the models behind it can change without an update.

- OpenRouter support. Add an OpenRouter key in Settings and generate with the models it offers. Add a Google AI Studio key, an OpenRouter key, or both; either one alone is enough.
- Choose a quality (Fast, Standard or Pro) and the app picks the model, or choose a specific model yourself from the list.
- If a model is unavailable, or one provider has no key or no credit, the app tries the other route and tells you what it did.
- Model changes arrive without an app update. The list of models, their prices and the tier each one serves are refreshed automatically, and you can load your own catalogue file from Settings.
- Vector images. Generate SVG assets, keep them in your library, and preview them safely.
- Every paid generation is now recorded in the spend log, even if you discard the image, so the totals always match what you were charged.
- Budget limits are checked against the model's price before anything is sent.
- Prompt refinement uses a current Claude model, and its settings are updated through the same catalogue.
- Claude Code can now ask for what it wants (a quality, vector or raster, reference images) with the new generate tool, and list what is available with list_generation_options. The existing generate_image tool still works.
- Safer library handling: a backup of your library is taken before any upgrade to its database, and the app will not open a library that iCloud has not finished downloading.

Your existing library and keys carry over unchanged.

Change any sentence that lists Imagen or Gemini 2.5 Flash Image as the supported models: the models are no longer fixed in the app.

Add to the privacy paragraph:

Your API keys are stored in your Mac's Keychain. Prompts and reference images are sent to the provider you choose, using your own key: Google when you generate with Gemini directly, openrouter.ai when you use OpenRouter, and Anthropic when you ask Claude to refine a prompt. The developer collects nothing and receives none of your prompts, images or keys. The app fetches its model catalogue from a public file; that request carries no information about you.

## Privacy manifest (PrivacyInfo.xcprivacy)

No change needed (spec section 5.9 confirmed against the code at d9b3add plus this pass):

- Declared: UserDefaults, reason CA92.1. Still used, for the app's own settings (library bookmark, budget ceiling, import naming, catalogue source). Nothing new needs a different reason.
- No use of file-timestamp APIs (no creationDate, modificationDate or their resource keys, no stat). The only resource keys read are the iCloud download status and file size, which are not required-reason APIs.
- No system boot time, disk space or active-keyboard APIs.
- Tracking stays false and collected data types stay empty: OpenRouter, Google and Anthropic receive data under the user's own key, and the developer collects nothing.
- App Privacy answers in App Store Connect stay "Data Not Collected".
